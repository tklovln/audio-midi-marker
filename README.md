## Audio MIDI Marker

This repo is a small Flask app for annotating MIDI notes against synchronized audio (and optional video).

### Data layout

The app discovers songs under:

- `/root/audio-midi-marker/data/<song-name>/`

Each `<song-name>` folder should contain:

- **Required**
  - `*.mid`
  - `*.wav` or `*.mp3`
- **Optional**
  - `*.mp4`
  - `annotation_revised.csv` (auto-created by the UI when you start saving annotations)
  - `ai_cache/` (generated by the AI fingering helper)

### Import from pooled files

If you already have pooled files like:

- `Paganini_Op01-01_AlicanSuner_lTsRFEpD6Jg-0001-0149_cut_trim.wav`
- `Paganini_Op01-01_AlicanSuner_lTsRFEpD6Jg-0001-0149_cut_trim.mp4`
- `Paganini_Op01-01_AlicanSuner_lTsRFEpD6Jg-0001-0149_trim.mid`

You can organize them into `data/<song-name>/` folders with:

```bash
python3 /root/audio-midi-marker/organize_data.py \
  --src /mnt/hdd/violin_media_outputs/Paganini \
  --dst /root/audio-midi-marker/data \
  --mode symlink \
  --dry-run
```

Then remove `--dry-run` to actually create folders and links:

```bash
python3 /root/audio-midi-marker/organize_data.py \
  --src /mnt/hdd/violin_media_outputs/Paganini \
  --dst /root/audio-midi-marker/data \
  --mode symlink
```

Notes:

- `--mode symlink` avoids duplicating large audio/video files.
- Use `--only-base Paganini_Op01-01_AlicanSuner` to test on a single piece first.
- If both `*_trim.mid` and `*_merge.mid` exist, you can choose with `--prefer-midi trim|merge`.

## Environment & dependencies

The runtime environment is managed with [uv](https://docs.astral.sh/uv/) and lives
**outside** this repo at `/home/tkwang/audio-midi-marker-env/` (venv + `pyproject.toml`
+ `uv.lock`). The app code stays here under `/nas_data/tkwang/audio-midi-marker`.

### Python packages

Python 3.10 (`requires-python = ">=3.10,<3.11"`). Declared in
`/home/tkwang/audio-midi-marker-env/pyproject.toml`:

| Package     | Constraint           | Installed |
| ----------- | -------------------- | --------- |
| flask       |                      | 3.1.3     |
| numpy       | `<2`                 | 1.26.4    |
| mido        |                      | 1.3.3     |
| soundfile   |                      | 0.14.0    |
| librosa     |                      | 0.11.0    |
| midi2audio  |                      | 0.1.1     |
| midiutil    |                      | 1.2.1     |
| tensorflow  | `>=2.14,<2.16`       | 2.14.0    |
| keras       | `>=3.0`              | 3.12.3    |

Important resolution constraints (do not "fix" these casually):

- **`numpy<2` is required.** TensorFlow 2.14 is built against NumPy 1.x; NumPy 2.x
  breaks its C extension import (`numpy.core._multiarray_umath failed to import`).
- **Keras 3 alongside TensorFlow 2.14.** TF 2.14 normally pins `keras<2.16`, but
  `ai_fingering.py` deliberately runs standalone Keras 3 via a compatibility shim
  (`_tf.keras = keras`). `pyproject.toml` uses `[tool.uv] override-dependencies`
  to force Keras 3 during resolution.

### System dependencies (optional, AI feature only)

`fluidsynth` and `ffmpeg` are **not installed** (no sudo on this host). They are only
needed by the AI fingering feature (MIDI-to-audio synthesis in `ai_fingering.py`).
The core annotation app runs fine without them, so it is started with
`ENABLE_FINGER_TRACKING=0`. Installing them (`apt install fluidsynth ffmpeg`) is
required to re-enable AI fingering.

### Frontend

- WaveSurfer is pinned to **v6.6.4** in `templates/annotation.html`. `static/js/app.js`
  uses the v6 API (`backend: "WebAudio"`, `wave.on("ready")`, etc.); WaveSurfer v7 has
  breaking changes and leaves the Play button stuck on "Loading…".

### Recreate the environment

```bash
# Install uv (per-user, no sudo needed)
curl -LsSf https://astral.sh/uv/install.sh | sh
source $HOME/.local/bin/env

cd /home/tkwang/audio-midi-marker-env
uv sync   # creates .venv from pyproject.toml + uv.lock
```

### Run the app

Use the launcher script (sets env vars, serves audio via the Flask `/audio` route
instead of Nginx, disables AI fingering):

```bash
/home/tkwang/audio-midi-marker-env/start.sh 5000   # port defaults to 5000
```

Notes:

- Do **not** set `STATIC_AUDIO_PREFIX` when running Flask standalone (no Nginx).
  Setting it makes audio URLs point at `/data/...` which 404s; leaving it unset uses
  the Flask `/audio/<song_name>` route.
- Flask runs without debug/reload, but `TEMPLATES_AUTO_RELOAD = True` is set in
  `create_app()`, so template edits take effect without a restart. Editing `app.py`
  still requires a restart:

```bash
pkill -f "flask run"
/home/tkwang/audio-midi-marker-env/start.sh 5000 > /home/tkwang/audio-midi-marker-env/server.log 2>&1 &
```
