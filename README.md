# Audio MIDI Marker

A lightweight Flask web app for annotating MIDI notes against synchronized audio
(and optional video). It was built to create note-level performance annotations
for violin recordings — tonal technique, articulation, string, hand position,
finger, and legato grouping — with an optional AI-assisted fingering suggestion
feature.

![status](https://img.shields.io/badge/status-release-blue)

## Features

- **Synchronized waveform + piano roll** — scrub the audio and see MIDI notes
  aligned on a shared timeline, with a configurable view window (5–20 s).
- **Per-note annotation** — click a note and set its attributes through radial
  (pie-chart) selectors:
  - Tonal technique
  - Articulation
  - String
  - Hand position
  - Finger
- **Legato grouping** — mark slurred/legato note groups; chord onsets within
  ±50 ms are detected and highlighted.
- **Box select** — batch-select multiple notes to annotate them at once.
- **Autosave** — annotations are written to a per-piece CSV as you edit.
- **Completion tracking** — mark each piece/performer as done; the index page
  shows per-piece progress.
- **Optional video playback** — if an `.mp4` is present it is served for
  reference (non-H.264 files are transcoded on the fly when `ffmpeg` is
  available).
- **Optional AI fingering** — generate string/position/finger suggestions from a
  pre-trained audio+symbolic model and review the diff before committing.

## Requirements

- Python 3.10 (`>=3.10,<3.11`)
- Core packages listed in [`requirements.txt`](requirements.txt)
- **Optional**, only for the AI fingering feature:
  - `fluidsynth` and `ffmpeg` system packages
  - The `Violin-Fingering-Generation-Through-Audio-Symbolic-Fusion` submodule and
    its model checkpoint

> **Note on NumPy:** `numpy<2` is required. TensorFlow 2.14 is built against
> NumPy 1.x and NumPy 2.x breaks its C-extension import.

## Installation

```bash
git clone https://github.com/tklovln/audio-midi-marker.git
cd audio-midi-marker

python3.10 -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
```

If you only want the core annotation app, you can skip the AI-only packages
(`midi2audio`, `midiutil`, `tensorflow`, `keras`).

## Data layout

The app discovers pieces under the `data/` directory next to `app.py`:

```
data/
  <Composer>_<SongName>_<Performer>/
    *.mid                    # required
    *.wav or *.mp3           # required
    *.mp4                    # optional (video reference)
    annotation_revised.csv   # auto-created when you start annotating
    status.json              # auto-created; stores the "completed" flag
    ai_cache/                # optional; generated by the AI fingering feature
```

The folder name is parsed as `{Composer}_{SongName}_{Performer}`, e.g.
`Paganini_Op01-01_AlicanSuner`. The first token is treated as the composer, the
last as the performer, and everything in between as the piece name.

### Importing from pooled files

If you have flat/pooled files such as:

```
Paganini_Op01-01_AlicanSuner_lTsRFEpD6Jg-0001-0149_cut_trim.wav
Paganini_Op01-01_AlicanSuner_lTsRFEpD6Jg-0001-0149_cut_trim.mp4
Paganini_Op01-01_AlicanSuner_lTsRFEpD6Jg-0001-0149_trim.mid
```

use `organize_data.py` to sort them into `data/<piece>/` folders. Start with a
dry run:

```bash
python3 organize_data.py \
  --src /path/to/pooled_files \
  --dst ./data \
  --mode symlink \
  --dry-run
```

Then drop `--dry-run` to actually create the folders and links:

```bash
python3 organize_data.py \
  --src /path/to/pooled_files \
  --dst ./data \
  --mode symlink
```

Options:

- `--mode {copy,symlink,hardlink}` — `symlink` avoids duplicating large media
  files (default: `copy`).
- `--only-base <NAME>` — only process a specific base folder name (repeatable),
  useful for testing a single piece first.
- `--prefer-midi {trim,merge}` — when both `*_trim.mid` and `*_merge.mid` exist,
  choose which one to use (default: `merge`).
- `--init-annotation` — pre-create `annotation_revised.csv` (with headers,
  synced to the MIDI notes) in each folder.

## Running the app

```bash
export FLASK_APP=app.py
flask run --host=0.0.0.0 --port=5000
```

Then open <http://localhost:5000>.

Notes:

- Templates auto-reload (`TEMPLATES_AUTO_RELOAD = True`), so template edits take
  effect without a restart. Editing `app.py` requires a restart.
- The AI fingering feature is disabled by default. To enable it (after
  installing its dependencies, see below), set `ENABLE_FINGER_TRACKING=1`.

### Serving media via Nginx (optional)

By default audio is served through the Flask `/audio/<song_name>` route. If you
put a static server (e.g. Nginx) in front of the app, you can serve the media
files directly and point the app at them by setting `STATIC_AUDIO_PREFIX`:

```bash
export STATIC_AUDIO_PREFIX="/data"
```

A sample `nginx.conf` is included. **Do not** set `STATIC_AUDIO_PREFIX` when
running Flask standalone (without a matching static server) — the audio URLs
would 404.

## Annotation CSV format

Annotations are stored per piece in `annotation_revised.csv` with these columns:

| Column           | Meaning                                             |
| ---------------- | --------------------------------------------------- |
| `pitch`          | MIDI note number                                    |
| `start`          | Note onset in seconds                               |
| `end`            | Note offset in seconds                              |
| `tonalTechnique` | Tonal technique label                               |
| `articulation`   | Articulation label                                  |
| `stringId`       | String index                                        |
| `position`       | Hand position                                       |
| `finger`         | Finger choice                                       |
| `legato`         | `1` if the note is part of a legato group, else `0` |

Notes are keyed by `(pitch, start)`. `organize_data.py` merges existing
annotations onto MIDI notes by matching pitch and approximate onset (within
50 ms), so re-importing never discards your work (a `.csv.bak` backup is kept).

## AI fingering (optional)

The AI fingering feature synthesizes the MIDI to audio, aligns it to the
recording, and runs a pre-trained audio+symbolic model to suggest
string/position/finger for each note. You can review the suggested diff and
commit it into the annotation CSV.

To enable it you need:

1. **System packages:** `fluidsynth` and `ffmpeg`
   ```bash
   sudo apt install fluidsynth ffmpeg   # Debian/Ubuntu
   ```
2. **The model submodule and checkpoint.** The model lives in
   `Violin-Fingering-Generation-Through-Audio-Symbolic-Fusion/`. Fetch it (and
   its checkpoint / soundfont) as described in that submodule's own README.
3. **Enable the feature** when starting the app:
   ```bash
   ENABLE_FINGER_TRACKING=1 flask run --host=0.0.0.0 --port=5000
   ```

The core annotation app runs fine without any of the above.

